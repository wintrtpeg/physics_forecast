# 미래 예측 — 계획을 넣고 앞으로를 예측한다

5단계(검증 결과)는 **과거를 되짚어** 채점합니다. 6단계(미래 예측)는 정답이 없는 **앞으로**
입니다. 입력(x)의 앞으로 값 — 생산계획의 가동률, 증설 후 장비 대수, 설정값, 기상 예보 — 을
넣으면 과거로 학습한 모델이 y 를 예측합니다.

```
과거 전체(기본) ──▶ 물리 파라미터 보정 + ML 학습 ──▶ 계획(x 만) ──▶ 예측
                                                          ├ 설비 상태 변동 폭 (물리모델)
                                                          ├ 학습 범위 밖 표시
                                                          └ 관리기준 초과 예상 시간
```

변수·모델·컬럼 연결·보정 파라미터·구성방정식 선택은 1~4단계에서 정한 것을 그대로 씁니다.
검증과 **같은 보정 코드**(`easy._fit_physics`)를 거치므로 검증한 모델과 예측하는 모델이 다르지
않습니다.

---

## ① 학습에 쓸 과거

| 선택 | 언제 |
|---|---|
| **데이터 전체 (기본, 권장)** | 운전 조건이 다양할수록 발생량과 제거효율 같은 파라미터가 서로 갈립니다 |
| 3단계 학습 기간만 | 검증한 모델과 똑같이 맞추고 싶을 때 |

**최근 몇 주만으로 다시 맞추지 마세요.** 학습 끝 3주로 재보정했더니 내부 검증 오차는 절반이
됐지만 증설 후 예측 오차는 세 배가 된 적이 있습니다 — 운전 다양성이 없어 파라미터 귀속이
바뀌고, 월말 계측 드리프트까지 흡수합니다 ([`improvement_log.md`](improvement_log.md)).

## ② 계획

두 가지 방법이 있습니다.

* **최근 패턴으로 만들기** — 최근 N일(기본 7일)의 입력을 M일(기본 14일) 동안 반복하고,
  바꿀 입력만 조정합니다: `× 배율`, `+ 더하기`, `= 고정값`. 값은 CSV 와 같은 단위입니다.
  만든 계획은 `plans/` 에 UTF-8(BOM) CSV 로 저장되어 엑셀에서 열어 고친 뒤 다시 올릴 수
  있습니다. 빈 시간(결측)은 **채우지 않습니다** — 그 시점의 예측이 비어 있을 뿐입니다.
* **계획 CSV 올리기** — 첫 컬럼은 시각, 나머지는 학습 CSV 와 **같은 이름·단위**의 입력 컬럼.
  y 는 없어도 됩니다. 현장 CSV 와 같은 수집기(`read_table`)로 읽으므로 CP949·여러 줄 헤더·
  ‘오후 3:05’ 날짜도 그대로 됩니다.

계획을 고르면 바로 검사합니다.

| 검사 | 결과 |
|---|---|
| 빠진 입력 컬럼 | 실행 막음 |
| 학습 데이터 끝 이전 시점 | 경고 — 과거 검증은 5단계에서 |
| 입력이 빈 행 | 경고 — 예측하지 않음 |
| 입력별 과거 범위 vs 계획 범위 | **학습 범위 밖 %** (입력별, 행 기준) |
| 과거에 한 번도 안 변한 입력이 계획에서 바뀜 | 경고 — ML 은 이 변화를 배울 방법이 없음 |

## ③ 결과

* **모델별 예측** — 물리모델, ML 다항(2차), ML 부스팅. 같은 과거 행·같은 입력으로 학습.
* **설비 상태 변동 폭** — 과거를 시간순 네 토막으로 나눠 토막마다 다시 보정하고, 각 토막의
  설비 상태로 계획을 풀어 본 범위(시점별 최소~최대). 긴 지평 예측의 불확실성은 파라미터
  공분산이 아니라 이 폭으로 말합니다 (`calib/design.state_paths`). 토막별 파라미터는 진단으로만
  보여주고 예측에 쓰지 않습니다.
* **학습 범위 밖 음영** — 계획 행 중 학습 때 없던 운전조건. 여기서 부스팅은 평평해지고
  다항식은 곡면을 그대로 연장합니다.
* **관리기준 초과 예상 시간** (1시간 평균) — 모델별, 그리고 상태 폭 상한이 넘는 ‘가능성’과
  하한까지 넘는 ‘확실’.
* 결과 CSV: `out/forecast/<이름>.forecast.csv` (계획 입력 + 모델별 예측 + 상태 폭 + 범위 밖 여부).

## 실제로 돌려 본 결과

### 계획 대신 실제 입력을 넣어 채점해 보기

미래 예측은 원래 채점할 수 없습니다. 그래서 경로가 맞는지 확인하려고, 현장형 더미
(`examples/nox_field/data/field_raw.csv`)의 **05-28 ~ 08-31 실제 입력만** 1시간 평균으로 떼어
계획 CSV 로 만들고(y 컬럼 없음), 과거 01-01 ~ 05-26 으로 학습해 예측한 뒤 따로 보관한 실측과
비교했습니다. 앱과 같은 설정(저장된 설정이 채운 연결, 보정 파라미터 6개)입니다.

| 모델 | 1시간 평균 RMSE (2,304시간) | 학습 범위 밖 시간만 (90%) | 편향 |
|---|---|---|---|
| 물리모델 | **2.83** mg/Nm3 | **2.66** | −0.09 |
| ML 다항(2차) | 11.03 | 11.61 | +8.72 |
| ML 부스팅 | 18.37 | 19.26 | −17.31 |

* 물리모델 상태 폭은 평균 폭 8.92 mg/Nm3 이고, 실측 1시간 평균의 **85.3%** 가 폭 안에
  들었습니다.
* 건식 장비 대수(`F2_FAB_DRY_EQP_CNT`)가 학습 동안 고정이었다가 계획에서 바뀐다는 경고가 떴습니다.
* 상태 폭 포함 176초 (보정 1회 + 토막 보정 4회 + 예측).

### 앱에서 끝까지 (브라우저)

같은 파일로 1~5단계를 마친 뒤 6단계에서 ‘데이터 전체’(01-01 ~ 08-31, 66,099행)를 학습에 쓰고,
‘최근 7일 패턴을 14일 반복 + 건식 가동률 × 1.1’로 계획(336시간)을 만들어 관리기준 100 으로
실행했습니다. 학습 범위 밖 11%(건식 가동률만), 129초. 물리모델 평균 103.5 mg/Nm3(95% 107.0),
ML 다항 104.7(초과 316시간), ML 부스팅 89.70(초과 0시간)이었고, 물리모델의 관리기준 초과 예상은
306/336시간, 상태 폭 기준 가능성 336시간 · 확실 166시간이었습니다. 부스팅은 최근 2주 실측(100 안팎)보다
낮은 90 근처에서 거의 평평했습니다 (최대 90.31). 이 실행에서 그 원인은 따로 확인하지 않았습니다. 다시 열면(시작 → 최근 프로젝트 → 미래 예측)
결과와 계획이 그대로 복원되고 실행 버튼이 바로 켜졌습니다.

## CLI

앱이 저장한 프로젝트(`projects/*.yaml`)를 그대로 씁니다.

```bash
pf project list                                       # 저장된 프로젝트
pf project run  <이름>                                # 같은 설정으로 다시 검증 (5단계)
pf forecast     <이름> --plan plans/계획.csv          # 계획 CSV 로 미래 예측
pf forecast     <이름> --days 14 --base-days 7 \
                --adjust F2_FAB_DRY_UTIL=scale:1.1 \
                --adjust F2_FAB_DRY_EQP_CNT=set:36    # 최근 패턴으로 계획을 만들어 예측
pf forecast     <이름> --history train --no-band      # 3단계 학습 기간만, 상태 폭 생략(빠름)
```

## API

| 엔드포인트 | 하는 일 |
|---|---|
| `POST /api/forecast/make` | 최근 패턴 + 조정으로 계획을 만들어 `plans/` 에 저장, 검사 결과·미리보기 |
| `POST /api/forecast/check` | 계획 CSV 검사 (빠진 컬럼, 과거 시점, 범위 밖, 고정 입력) |
| `POST /api/forecast/run` | 미래 예측 (비동기, `job`). `history: [시작, 끝]` 또는 `null`(전체), `band` |
| `GET /api/forecast/plans` | `plans/`·`uploads/` 의 계획 CSV 목록 |

계획 CSV 는 `/api/workspace` 의 데이터 목록에 섞이지 않습니다 (학습 데이터가 아니므로).
