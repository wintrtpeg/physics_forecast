# 모델 만들기 — 코드 없이 계통을 조립한다

물리모델은 **계통 구조**(무엇이 무엇에 연결되는가)를 알아야 만들 수 있고, 그 구조는 데이터에서
유도할 수 없습니다. 그래서 구조는 사람이 정하고, 이 화면은 그 일을 코드 없이 하게 해 줍니다.
만든 모델은 `system.yaml` 과 같은 형식의 파일이라 4단계(모델·실행)와 시나리오 화면, CLI
(`pf check`, `pf solve`, `pf calibrate`)에서 그대로 씁니다.

```
[컴포넌트 목록] ──눌러서 추가──▶ [흐름도 · 컴포넌트 카드 · 연결 · 선언] ──▶ [검사]
                                                                         불러오기 → 연결 → 구조 → 설계점 풀이
```

## 순서

1. **컴포넌트 추가** — 왼쪽 목록에서 누릅니다. 분류별로 나뉘고 점 색이 포트 종류입니다
   (가스·열·액체·전력). 비슷한 계통이 있으면 위의 **열기 · 템플릿에서 시작**으로 복사해서
   고치는 게 빠릅니다. 예제(`examples/`)는 덮어쓰지 않고 `models/` 에 사본으로 저장합니다.
2. **연결** — 출구 포트 → 입구 포트. 같은 종류의 포트만 고를 수 있습니다. 연결점에서는
   압력(온도)이 같고 유량(열류)의 합이 0 입니다.
3. **파라미터** — 컴포넌트 카드에서 설계값을 선언한 단위로 고칩니다. `보정` 배지가 붙은 것은
   데이터로 맞출 수 있는 물리 파라미터입니다. 구성방정식 슬롯이 있는 컴포넌트는 후보도 고릅니다
   ([`closures.md`](closures.md)).
4. **선언** — 이 모델을 어떻게 쓰는지 적습니다.
   * 운전 손잡이: 미리 아는 값(생산계획·설정값·예보). 시나리오 화면의 슬라이더가 됩니다.
   * 계측값: 현장에서 재는 출력. 간편 예측에서 CSV 컬럼을 연결할 후보가 됩니다.
   * 기본 보정 파라미터: 식별 가능한 것만 적게.
   * 관리기준: 상한·하한.
5. **저장** — `models/<이름>.yaml`. 검사 결과가 ‘풀립니다’이면 **이 모델로 예측하기 →** 로
   간편 예측 4단계로 넘어갑니다 (컬럼 연결·보정 파라미터·구성방정식 선택은 새로 합니다 —
   다른 계통의 이름이 따라붙지 않게).

## 검사 — 고칠 때마다 자동으로

| 단계 | 막히는 경우 |
|---|---|
| 불러오기 | 모르는 컴포넌트 종류, 잘못된 파라미터 이름·값, 선언형 식의 문법·차원 오류 |
| 연결 | 없는 포트, 종류가 다른 포트끼리, **연결 안 된 포트** (계통 끝은 경계 컴포넌트로 닫기) |
| 구조 | 방정식 수 ≠ 미지수 수 — 어느 쪽이 남거나 모자라는지 변수·식 이름으로 |
| 설계점 풀이 | 뉴턴법이 수렴하지 않음 — 어느 BLT 블록의 어느 변수/방정식인지 |

통과하면 방정식·미지수 개수, BLT 블록 수, 설계점 결과(컴포넌트별 출력)가 나옵니다.
선언에 모델에 없는 변수가 있으면 경고합니다.

`examples/chiller_plant/system.yaml` 을 템플릿으로 열면 방정식 25 = 미지수 25, 컴포넌트 5개,
연결 6개, BLT 블록 19개(최대 7)로 풀립니다. 연결 하나(`LOAD.out → CHILLER.evap`)를 지우면
‘연결 단계에서 막힘 — 연결되지 않은 포트: LOAD.out, CHILLER.evap’ 이 뜨고, 다시 이으면
풀립니다 (브라우저로 확인).

## 컴포넌트는 어디서 오나

| 출처 | 예 | 추가하는 법 |
|---|---|---|
| 파이썬 컴포넌트 (`lib/`) | 덕트, 송풍기, 헤더, 배기원, 스크러버, 굴뚝 | [`adding_components.md`](adding_components.md) |
| **라이브러리 YAML** (`lib/components/*.yaml`) | 냉방부하, 칠러(카르노 효율형), 냉각탑, 외기 열싱크, 플랜트 배전반 | YAML 한 파일 — 모델에서 `spec: "lib:이름"` 으로 참조 |
| **작업 폴더 YAML** (`components/*.yaml`) | 현장 고유 장비 | 같은 형식으로 작업 폴더에 두면 목록에 뜸 |
| 사용자 정의 | 목록 맨 아래 | 화면에서 포트·파라미터·변수·식을 직접 적음 |

선언형 컴포넌트 YAML:

```yaml
# src/pforecast/lib/components/cooling_tower.yaml (발췌)
title: 냉각탑 (접근온도차형)
category: 열·냉동
description: 냉각탑. 접근온도차가 부하에 따라 커지는 것이 핵심 비선형이다.
ports:
  hot:  {kind: thermal, role: in,  T_start: 305.15, Q_start: 4.2e+6}
  amb:  {kind: thermal, role: out, T_start: 300.15, Q_start: 4.2e+6}
  elec: {kind: power,   role: out, P_start: 2.0e+5}
params:
  app_nom: {value: 5.0, unit: K, desc: 정격 접근온도차, lo: 1.0, hi: 15.0, tunable: true}
  app_exp: {value: 0.5, unit: '1', desc: 부하 지수, lo: 0.1, hi: 1.5, tunable: true}
  Q_nom:   {value: 4200.0, unit: kW, desc: 정격 방열량}
vars:
  approach: {unit: K, start: 5.0, lo: 0.2, hi: 30.0, desc: 접근온도차}
equations:                       # 이름 붙인 잔차식 — 진단 메시지에 TOWER.closure 처럼 뜬다
  heat: hot.Q + amb.Q = 0
  temp: hot.T = amb.T + approach
  closure: approach = app_nom * (hot.Q / Q_nom) ^ app_exp
outputs:
  T_cw: {expr: hot.T, unit: degC}
```

YAML 1.1 은 `4.2e6` 을 문자열로 읽습니다 — `4.2e+6` 으로 적으세요 (읽는 쪽에서도 방어합니다).

새 계통(냉동기, CDA, 외조기)은 여기에 컴포넌트를 더하는 것으로 끝나야 합니다. `core/` 를
고쳐야 한다면 추상화가 부족한 것이니 먼저 논의합니다 (CLAUDE.md).

## API

| 엔드포인트 | 하는 일 |
|---|---|
| `GET /api/builder/palette` | 컴포넌트 목록 (파이썬 + 라이브러리 + 작업 폴더 + 빈 템플릿) |
| `POST /api/builder/load` | 모델 파일을 화면용 dict 로 |
| `POST /api/builder/check` | `{model}` 또는 `{yaml}` 을 검사 (파일은 쓰지 않음). 단계·오류·개수·설계점 결과 |
| `POST /api/builder/save` | 작업 폴더 안 `.yaml` 로만 저장 (기본 `models/`) |
