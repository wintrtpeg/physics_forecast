# 데이터 주도 분석 — 타깃 컬럼만 지정해서 어디까지 갈 수 있나

`pf analyze` 는 시계열 센서 데이터와 타깃 컬럼 하나를 받아 **자동으로 갈 수 있는
데까지 사다리를 올라가고, 어디서 왜 막혔는지 알려준다.**

```bash
pf analyze examples/nox_stack/analysis.yaml
```

---

## 1. 사다리

| 단계 | 내용 | 필요한 것 | 자동? |
|---|---|---|---|
| **L0** | 데이터 프로파일링, 운전 포락선, 준정상 구간 | 데이터만 | ✅ |
| **L1** | 대리모델 + XAI (중요도·부분의존도·지연) | 타깃 지정 | ✅ |
| **L2** | 차원 해석 — 무차원군(Buckingham Π) | **컬럼 단위** | ✅ |
| **L3** | 보존식 자동 탐지 | **컬럼 단위** | ✅ |
| **L4** | 구조 지배방정식 모델 | **계통 토폴로지 + 설비 제원** | ❌ |
| **L5** | 하이브리드 (물리 + 잔차 ML) | L4 | ❌ |

### L4 를 자동화할 수 없다는 것이 이 설계의 핵심 제약이다

컬럼 이름과 숫자만 보고 "이건 스크러버이고 뒤에 팬이 달려 있고 그 사이에 덕트가
있다"를 유도할 수는 없다. **토폴로지는 물리적 사실이지 데이터의 통계적 성질이
아니다.** 그래서 L4 는 언제나 "막힘"으로 보고되고, 대신 무엇을 주면 열리는지
구체적으로 알려준다: 컴포넌트 목록, 연결 관계, 설계 제원 세 가지다.

LLM 이 태그 이름(`F2_UT_SCR01_FAN_SP`)을 읽고 토폴로지를 **제안**할 수는 있다.
하지만 그건 제안이고, 사람이 확인해야 한다. 툴은 제안된 구조를 차원 검사와 구조
해석으로 **검증**해 준다.

## 2. L1 의 함정 — 실제로 겪은 것

예제 데이터(굴뚝 NOx, 30일 5분 평균, 합성)로 돌린 결과다. 진짜 기여도를 알고
만든 데이터라 답을 맞춰 볼 수 있다.

**진짜 기여도** (가동율 80% 기준):

| 장비군 | NOx 발생량 | 비중 |
|---|---|---|
| DRY | 184.3 mg/s | **60.4%** |
| CVD | 74.3 | 24.4% |
| IMP | 24.2 | 7.9% |
| WET | 22.2 | 7.3% |

**개별 순열 중요도가 내놓은 순위**:

| 피처 | 중요도 | 최대 상관 |
|---|---|---|
| WET_UTIL | **35.5%** | 0.999 |
| CVD_UTIL | 22.4% | 0.9996 |
| IMP_UTIL | 13.9% | 0.9996 |
| DRY_UTIL | **11.4%** | 0.9996 |

**완전히 뒤집혔다.** 실제 1위(60%)가 4위(11%)로, 실제 꼴찌(7%)가 1위(36%)로
나왔다. 모델 성능은 멀쩡하다 (교차검증 R² = 0.939).

원인은 명확하다. 네 가동율의 상호 상관이 **0.9996** 이다. 순열 중요도는 상관된
변수들 사이에서 기여를 **임의로 나눠 갖는다** — 모델이 어느 변수를 먼저 썼는지에
따라 달라질 뿐 인과의 크기가 아니다.

### 고친 방법: 상관 묶음 단위로 재기

상관 0.9 이상인 피처를 연결요소로 묶고, 묶음 안의 열을 **같은 순열로 함께** 섞는다.
묶음 내부의 상관 구조는 유지한 채 묶음 전체와 타깃의 연결만 끊으므로, 구분되지
않는 변수들의 기여를 하나로 합쳐 정직하게 잰다.

결과:

| 인자 묶음 | 중요도 | 개별 분해 |
|---|---|---|
| 지류유량 4 + 헤더유량 + 굴뚝유량 + 스크러버차압 + 가동율 4 (총 11개) | **93.2%** | **불가 (내부 상관 0.9996)** |
| 송풍기 주파수 | 2.6% | 가능 |
| 송풍기 정압 | 1.6% | 가능 |
| 굴뚝 온도 | 1.4% | 가능 |

이제 정직하다. **"영향의 93% 가 서로 구분되지 않는 한 덩어리에 있다. 이 안에서
누가 원인인지는 이 데이터로 알 수 없다."**

그리고 이게 물리 모델이 필요한 이유다. 지배방정식에서는 각 장비군의 배출계수가
**각자의 질량수지에 구조적으로 다른 자리로** 들어가므로, 상관이 높아도 분리
가능성이 생긴다. (그래도 분리가 안 되면 캘리브레이션의 식별성 진단이 그렇다고
말해 준다 — 실제로 이 예제에서 배출계수와 제거효율이 곱으로만 결정된다고 경고했다.)

## 3. L3 — 데이터가 스스로 말해 주는 지배방정식

같은 차원을 가진 컬럼 묶음에서 `Σ aᵢxᵢ ≈ 0` 인 선형 관계를 찾는다. 예제에서:

```
[확실]      BR_DRY + BR_CVD + BR_WET + BR_IMP − HDR = 0    잔차 0.31%, R² 0.986
[우연 의심] BR_DRY − BR_WET = 0                             잔차 2.00%, R² 0.479
```

첫 번째는 **질량 보존**이다. 회귀계수가 아니라 물리 제약이므로 외삽 구간에서도
성립한다. 두 번째는 크기가 비슷한 두 신호가 우연히 맞아떨어진 것이고, R² 가 낮아
자동으로 "우연 의심"으로 분류됐다.

### 왜 SVD 가 아니라 정수 열거인가

처음에는 SVD 의 최소특이벡터를 썼다. 결과는 `4·DRY + 4·CVD + 3·WET − 3·IMP −
3·HDR = 0` — 계수가 엉망이었다. 현장 데이터는 거의 언제나 강하게 공선적이라(전부
가동율이 끌고 간다) 영공간 근처에 방향이 여러 개 있고, 그중 **가장 작은 것은
노이즈가 고른다.**

보존식의 계수는 현실에서 거의 항상 ±1 이다. 그래서 `{−1, 0, +1}` 조합을 전부
열거하고 잔차를 재는 쪽이 옳다. 결과가 사람이 읽을 수 있는 형태로 나온다.

> SINDy 류의 희소회귀와 다른 점도 여기다. 차원을 무시하고 항 사전을 훑으면
> 현장 노이즈에서 무너지고, 차원이 안 맞는 — 즉 물리적으로 불가능한 — 식을
> 내놓는다. 후보를 **같은 차원끼리의 선형결합**으로 제한하면 나오는 식이 항상
> 차원적으로 옳다.

## 4. L2 — 무차원군

차원 행렬의 영공간에서 무차원 조합을 만든다. 검증으로 관내 압력손실 문제를 넣으면
**레이놀즈수와 오일러수**가 정확히 나온다 (`tests/test_dimensional.py`).

```python
units = {"rho": "kg/m3", "v": "m/s", "L": "m", "mu": "Pa*s", "dp": "Pa"}
# -> ρvL/μ  (Reynolds),  ρv²/Δp  (Euler)
```

Π 공간에서 회귀하면 모델이 **상사법칙을 정확히 만족**한다. 순수 회귀와 달리 스케일
방향으로는 외삽이 성립하므로, 물리모델과 ML 사이의 중간 사다리로 쓸 수 있다.

단, 변수 수가 차원 수보다 충분히 많아야 자명하지 않은 군이 나온다. 예제의 NOx
데이터에서는 대부분 단일 무차원 컬럼이라 얻은 게 적었다 — 툴이 그렇게 보고한다.

## 5. 개선 제안과 그 한계

제어 가능하다고 표시한 변수만 격자 탐색한다. **학습 포락선 밖은 제안하지 않는다** —
대리모델은 그 밖에서 아무 근거가 없다.

예제에서는 송풍기 주파수를 59.1 Hz 로 낮추면 NOx 가 1.0% 준다는 답이 나왔다.
그런데 **물리 모델은 정반대로 말한다** — 팬을 늦추면 유량이 줄어 희석이 덜 되고
농도가 오른다 (`pf run` 의 팬 감속 시나리오에서 85% 감속 시 +15%).

툴은 이 제안에 경고를 붙인다: *"제어변수의 영향력이 전체의 2.6% 뿐입니다. 이
제안은 믿지 마세요 — 약한 신호에서 나온 방향은 부호가 뒤집히기도 합니다.
물리 모델로 교차검증해야 합니다."*

**이게 하이브리드의 실제 모습이다.** ML 이 제안하고 물리가 검증한다. 둘 중 하나만
쓰면 이런 부호 오류를 잡을 수 없다.

## 6. 설정

```yaml
data:
  csv: data/plant_5min.csv
  timestamp: timestamp

target:
  column: F2_UT_STK01_NOX_DRY
  unit: mg/Nm3

units:                        # ★ 이걸 채워야 L2/L3 가 열린다
  F2_UT_SCR01_BR_DRY_FLOW: kg/s
  F2_UT_SCR01_HDR_FLOW:    kg/s
  F2_UT_STK01_TEMP:        degC
  ...
# units_from_tagmap: tagmap.yaml    # 기존 태그맵 재사용도 가능

controllable: [F2_UT_SCR01_FAN_HZ]  # 개선 탐색은 여기만 움직인다
objective: minimize

split:
  train_fraction: 0.6         # 시간순 앞 60%. 무작위 분할 금지.

report: out/analysis.html
```

`units:` 를 비워도 L0/L1 은 돈다. 하지만 그건 그냥 ML 이다. **단위 한 줄이
L2/L3 를 열고, 거기서 물리가 나온다.**

## 7. 대시보드가 보여주는 것 (XAI)

1. **먼저 읽을 것** — 숫자보다 먼저 '이 숫자를 어떻게 읽어야 하는가'
2. **분석 사다리** — 각 단계 상태 / 결과 / 막힌 이유 / 푸는 법
3. **자동 발견 물리** — 보존식, 무차원군
4. **예측 성능** — 시간블록 교차검증 시계열·대응도 (무작위 k-fold 아님)
5. **영향인자** — 묶음 기준 먼저, 개별은 얽힘 경고와 함께, 부분의존도
6. **외삽 경고** — 학습 포락선과 검증구간 이탈 비율
7. **개선안** — 제안값, 포락선 이탈 여부, 신뢰도 경고
8. **한계** — 명시

## 8. 정직한 한계

* **대리모델은 학습 포락선 안에서만 유효하다.** 증설·설비교체·운전방식 변경처럼
  과거에 없던 조건은 원리적으로 답할 수 없다. 그건 L4 의 일이다.
* **영향인자는 상관이지 인과가 아니다.** 한 덩어리로 묶인 변수들 사이에서는 순위
  자체가 의미 없다.
* **보존식 탐지는 같은 차원 컬럼이 2개 이상 있어야** 동작한다. 지류별 유량계처럼
  합이 맞아야 하는 계측을 함께 넣을수록 많이 찾는다.
* **토폴로지는 데이터에서 유도할 수 없다.** 이건 도구의 한계가 아니라 문제의
  성질이다.
