# 로컬 웹 앱

```bash
pip install -e ".[plot,ml]"
pf serve                       # 또는 python -m pforecast.app
```

브라우저가 뜨고 `http://127.0.0.1:8765` 에 붙습니다. **의존성은 표준 라이브러리뿐**
입니다 — FastAPI 도 Streamlit 도 쓰지 않습니다. 사내 잠긴 PC 에서 한 줄로 떠야 하고,
프레임워크가 하나라도 막히면 도구 전체가 멈추기 때문입니다. 프런트엔드도 CDN 을
쓰지 않아 외부 요청이 **0건** 입니다.

```
pf serve --root D:\work\utility   # 작업 폴더 지정 (CSV·모델을 여기서 찾습니다)
pf serve --port 9000 --no-browser
```

## 화면 흐름

### 1. 데이터 — 단위 지정이 전부입니다

작업 폴더의 CSV 를 훑어 목록으로 보여주고, 고르면 프로파일링합니다.

* **현장 파일을 있는 그대로 읽습니다** — CP949(한글 엑셀), 태그/설명/단위 여러 줄 헤더,
  `2025-01-01 오후 3:05` 날짜, `Bad`·`Comm Fail`·`#N/A` 상태 문자열, 천 단위 콤마,
  이어 붙인 파일의 중간 헤더·겹친 구간·뒤바뀐 순서. 엑셀에서 손질할 필요가 없습니다.
* **데이터 정리 내역** 카드 — 파일에서 고친 것과 값에서 뺀 것을 전부 적습니다.
  조용히 고치지 않습니다.
* 값 이상 탐지: 분석계 **정기 교정 창**(매일 같은 시각의 영점/스팬), **고착**(마지막 값
  유지), **스파이크**(단선 999.9 등), 1시간 갱신 집계값, 장기 결측. 값이 정확히 0 으로
  유지되는 구간(펌프 정지)은 설비 정지로 보고 지우지 않습니다.
* 컬럼 이름을 누르면 시계열이 뜨고, **결측 처리한 점이 빨간 점**으로 원래 값 그대로
  찍힙니다. 무엇을 왜 뺐는지 눈으로 확인하세요.
* 컬럼별 범위·결측·상수·중복 판정, 이상 배지
* **파일에 단위 행이 있으면 그것을**, 없으면 태그 이름에서 단위를 추론 — 노란 칸은
  신뢰도가 낮으니 확인하라는 뜻
* 타깃 컬럼과 제어 가능 변수를 체크

단위를 왜 이렇게 강조하느냐면, **단위가 있어야 차원 해석(L2)과 보존식 탐지(L3)가
열리기 때문**입니다. 단위 없이도 ML 은 돌지만 그건 그냥 ML 입니다.

추론 규칙은 국내 팹 태그 관례를 따릅니다. `_TEMP`→degC, `_NOX`→mg/Nm3,
`_UTIL`→%, `_HZ`→Hz, `_DP`/`_SP`→mmAq 등. 유량과 압력은 이름만으로 못 정하므로
**값의 크기**로 후보를 고르고 확인을 요청합니다 (예: 대푯값 1.4 → kg/s, 13,000 → Nm3/h).

### 2. 분석 — 사다리를 어디까지 올라갔나

`pf analyze` 와 같은 내용을 화면으로 봅니다. 요약 타일, 먼저 읽을 문장, 사다리
5단계 상태, 자동 발견한 보존식, **묶음 기준 영향인자**, 교차검증 예측 추종.

영향인자를 묶음 기준으로 먼저 보여주는 이유는 `docs/data_driven.md` 에 있습니다 —
개별 순열 중요도는 상관된 변수 사이에서 순위가 뒤집힙니다.

### 3. 물리모델 — 풀기 전에 구조부터

모델을 고르면 조립하고 구조를 검사합니다. 방정식/미지수 개수, BLT 블록 구조,
야코비안 non-zero 개수, 컴포넌트 목록.

### 4. 시나리오 — 손잡이를 끌면 그 자리에서 다시 풉니다

**이 화면이 물리 모델을 쓰는 이유를 체감시키는 곳입니다.**

정상상태 1회가 4~15 ms 라 슬라이더가 즉각 반응합니다. 과거 데이터에 한 번도 없던
조건(증설, 설비 교체, 극한 기상)을 끌어봐도 답이 나옵니다 — ML 대리모델이
원리적으로 못 하는 일입니다.

* 손잡이는 모델이 `DRIVERS` 로 선언합니다 (없으면 자동 추출)
* 관리기준(`LIMITS`)이 걸린 출력은 KPI 타일에서 초과 시 빨갛게 표시
* 민감도 스윕: 손잡이 하나를 끝에서 끝까지 훑어 곡선과 관리기준선을 같이 그림
* 스윕 캡션이 **변화폭을 %로** 알려줍니다. 세로축 눈금이 좁으면 기울기가 커 보이는데,
  실제로는 영향이 없는 경우를 구분하기 위해서입니다

## 운전 손잡이 선언

모델이 직접 선언하는 편이 훨씬 낫습니다. 자동 추출은 대기압·기준밀도 같은 상수까지
손잡이로 끌어옵니다.

```python
# model.py
DRIVERS = [
    {"key": "util",    "label": "가동율",        "unit": "%",     "lo": 20,  "hi": 130},
    {"key": "n_tools", "label": "장비 대수",      "mode": "scale", "lo": 0.5, "hi": 2.0},
    {"key": "T_amb",   "label": "외기온도",       "unit": "degC",  "lo": -10, "hi": 40},
]
LIMITS = {
    "STK.C_dry": {"max": 100.0, "label": "사내 관리기준"},
    "SRC_DRY.q_per_tool": {"min": 3.0, "label": "후드 포집 한계"},
}
```

YAML 모델도 똑같이 `drivers:` / `limits:` 로 선언합니다.

`key` 는 파라미터 이름의 **마지막 조각**입니다. `SRC_DRY.util`, `SRC_CVD.util` …
네 개가 손잡이 하나로 묶입니다. 팹 계통은 같은 종류 설비가 여러 대 붙는 구조라
이 규칙이 잘 맞습니다.

`mode: scale` 은 절대값이 아니라 **설계 대비 배율**입니다. 장비 대수처럼 군마다
값이 다른 것에 씁니다.

## API

앱은 얇은 JSON API 위에 올라가 있습니다. 다른 도구에 붙일 때 그대로 쓰면 됩니다.

| 엔드포인트 | 하는 일 |
|---|---|
| `GET /api/workspace` | 작업 폴더의 CSV·모델 목록 |
| `POST /api/profile` | 수집·정리 내역 + 값 이상 + 프로파일링 + 단위 |
| `POST /api/preview` | 컬럼 시계열 (다운샘플) + 결측 처리한 점 |
| `POST /api/analyze` | 분석 사다리 실행 (비동기, `job` 반환) |
| `GET /api/job?id=` | 작업 상태 폴링 |
| `POST /api/model/meta` | 구조 진단 + 손잡이 + 출력 + 관리기준 |
| `POST /api/model/solve` | 정상상태 1회 (4~15 ms) |
| `POST /api/model/sweep` | 손잡이 하나를 훑으며 연속 풀이 |

긴 작업만 스레드로 돌리고 나머지는 요청 안에서 바로 처리합니다. 컴파일된 모델은
캐시하고 직전 해를 warm start 로 재사용합니다.

## 알아둘 것

* **보안**: `127.0.0.1` 에만 바인딩합니다. 작업 폴더 밖 경로는 거부합니다.
* **데이터는 서버로 나가지 않습니다.** 전부 로컬에서 처리됩니다.
* 10MB(7만 행 × 25 태그) CSV 의 첫 읽기·정리는 약 3초, 이후엔 캐시에서 0.2초입니다.
  파일이 바뀌면(수정 시각·크기) 다시 읽습니다.
* `_` 로 시작하는 폴더(예: 더미 데이터의 정답지 `_answer/`)는 목록에 뜨지 않습니다.
* 모델 파일을 고치고 나면 물리모델 화면의 **다시 불러오기**를 누르세요.
