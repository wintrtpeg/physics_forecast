# 현장형 더미 데이터 스트레스 테스트

실데이터가 없는 상태에서 "현장 데이터를 넣으면 정말 돌아가는가"를 확인하려고,
**일부러 지저분하게 만든 8개월치 데이터**를 만들어 툴 전체를 통과시켰습니다.
문제를 어디에 숨겼는지 정답지를 따로 두고, 툴이 그것을 얼마나 찾아내는지 채점했습니다.

```bash
python examples/nox_field/make_field_data.py      # 데이터 + 정답지 생성 (약 7분)
python examples/nox_field/evaluate.py             # 채점 (약 12분) → examples/nox_field/out/scorecard.md
```

이 문서의 수치는 전부 위 두 명령을 실제로 돌려서 나온 값입니다 (`scorecard.json`).

## 1. 무엇을 숨겼나

물리는 `nox_stack` 모델로 7만 회 정상상태를 풀어 만들었습니다. 다만 **현장은 모델과
다르게** 만들었습니다 — 모델이 모르는 변화와 모델 자체의 오차를 넣었습니다.

| 층 | 숨긴 것 |
|---|---|
| **공정** (모델이 모르는 것) | 4/7 DRY 레시피 변경 → 배출 +15% (비계측) · 충전재 오염으로 효율·차압이 서서히 나빠지다 6/21 세정으로 복원 · 덕트 분진 퇴적 · CVD 챔버 클리닝 NOx 펄스 하루 3회 · 팬 마모(성능곡선이 설계와 다름) · NTU 지수 0.62 (모델은 0.55) |
| **운전** | 1/28 설 연휴 감산 · 5/3~5 팹 정기 PM · 4/15, 6/21 순환펌프 정지(유량 0) · **6/10 DRY 장비 24→30대 증설** · 7/1 순환수 증량 · 여름 폭염 |
| **계측** | NOx 분석계 매일 03:00 영점→스팬(160) 자동 점검 · 월 1회 수동 교정 사이 드리프트 · 응답 지연 · 7/15 분석계 교체(−3) · 유량계 56시간 고착 · 열전대 단선(999.9, −40) · 5/28 정압 전송기 교체(+12 mmAq) · IMP 지류 유량계 4/1 고장 · 헤더 유량계 +3% 게인 · 예비 온도계 +0.45 ℃ · MES 가동율 1시간 갱신 |
| **파일** | CP949 · 태그/설명/단위 3행 헤더 · 첫 컬럼 '일시' · 1~3월 `2025-01-01 오후 3:05` 표기와 천 단위 콤마 · `Bad`/`Comm Fail`/`I/O Timeout`/`Maint`/`#N/A` · 월별 파일을 이어 붙이며 생긴 중간 헤더, 72행 중복, 7·8월 순서 뒤바뀜 · 3/9 하루 누락 · 끝 콤마 빈 컬럼 · 빈 줄 · 방해 컬럼(pH, 레벨, 펌프 교대, 죽은 예비 입력) |

## 2. 고치기 전 — 기존 툴은 첫 바이트에서 죽었다

| 경로 | 결과 |
|---|---|
| `pf analyze` / `pf calibrate` / 앱 데이터 화면 | `UnicodeDecodeError` (CP949) |
| 사용자가 UTF-8 로 다시 저장한 뒤 | 26개 컬럼 중 **25개가 문자열이 되어 조용히 버려짐**. `오전/오후` 표기 25,671행(**37%**)이 경고 없이 사라짐. 오류 메시지는 "CSV 에 없는 태그" — 원인과 무관한 안내 |

조용히 틀리는 쪽이 더 위험합니다. 엑셀에서 헤더를 손으로 지웠다면 석 달 치가 빠진
채로 분석이 "성공"했을 것입니다.

## 3. 고친 뒤 — 채점 결과

### 파일 읽기 (`data/ingest.py`)

주입한 파일 결함을 전부 찾아 고치고, 고친 내역을 문장으로 보고합니다.

* CP949, 3행 헤더 인식 — 단위 행에서 23개 컬럼의 단위를 읽음 (`mg/Sm³`→`mg/Sm3`, `㎥/h`→`m3/h`, `℃`→`degC`, `대`→`1`)
* 시각: `오전/오후` 25,671행 + ISO 44,018행, 해석 불가 **0**
* 반복 헤더 6행, 중복 **72행 (주입 72)**, 순서 뒤바뀜 2곳, 빈 컬럼 1개
* 상태 문자열: Bad 44,090 · Comm Fail 1,728 · I/O Timeout 810 · Maint 720 · #N/A 576
* 천 단위 콤마 25,547셀
* 5분 격자 69,984행으로 정렬, 빠진 시각 367개(3/9 하루 포함)는 빈 행으로

10MB 파일 첫 읽기 약 3초, 앱에서는 이후 캐시.

### 값 이상 탐지 (`data/quality.py`)

| 태그 | 주입 | 탐지 | 놓침 | 오탐 |
|---|---:|---:|---:|---:|
| 굴뚝 NOx (교정 창 1,074 + 스파이크 12) | 1,086 | 1,086 | 0 | 0 |
| 굴뚝 유량 (고착 671 + 스파이크 14) | 685 | 685 | 0 | 0 |
| 굴뚝 온도 (단선) | 6 | 6 | 0 | 0 |

정상 점 1,617,856개 중 **오탐 0**. 정기 교정은 "매일 03:00~03:25 에 215일 반복 — 분석계
영점/스팬 점검으로 보입니다"로 따로 분류합니다. 펌프 정지(유량이 정확히 0)는
**고착이 아니라 설비 정지로 보고 지우지 않습니다** — 그 구간 NOx 상승은 진짜 공정이고,
모델이 배워야 하는 것입니다.

만들면서 실제로 걸린 함정 두 개:
* 교정 창 옆 행이 비어 있으면 이동 중앙값이 교정값에 끌려가 멀쩡한 이웃 점 5개가
  스파이크로 잡혔습니다 → 교정 창을 먼저 빼고 다시 봅니다.
* 기존 예제의 인버터 주파수(0.01 단위 반올림)에서 잡음 추정이 0 에 붙어 오탐 4건이
  났습니다 → 잡음 하한을 신호 분해능으로.

### 데이터 주도 분석 (L0~L3)

* 대리모델 R² 0.719 (시간블록 교차검증). 검증 구간 90% 가 학습 포락선 밖.
* **"F2_FAB_DRY_EQP_CNT 는 학습 구간 내내 24 에서 변하지 않다가 검증 구간에서 24~30 으로
  바뀝니다. 대리모델은 이 변수의 효과를 배울 방법이 없어서 뺐습니다."** — 증설처럼
  ML 이 원리적으로 못 보는 변화를 스스로 짚습니다. (처음엔 이 컬럼 때문에 pandas 3 의
  `idxmax` 가 예외를 내며 L1 전체가 막혔습니다.)
* 보존식이 **계측기를 진단**합니다:
  * 지류 4개 합 = 헤더 → "헤더 유량계가 지류 합보다 **+3.0%** 높게 읽습니다 — 계측기
    교정 오차로 보입니다" (주입 3%). IMP 지류 유량계가 4월에 죽었는데도, 살아 있던
    1~3월 구간으로 찾았습니다.
  * 굴뚝 온도 2개 → "예비 온도계가 평균 **0.451 ℃** 높게 읽습니다 — 이중화 계측의
    영점 오차" (주입 0.45). ℃ 처럼 영점이 임의인 단위는 비율 대신 차이로 말합니다.

### 물리모델 vs ML — 1~5월로 학습, 증설 후 6/10~8월 예측

검증 구간은 장비 대수(24→30), 가동율, 외기온도가 전부 학습 범위 밖입니다.
같은 학습 데이터, 같은 운전 입력(가동율·대수·외기·팬·순환수)으로 비교했습니다.
**참값**은 계측 오차가 없는 진짜 NOx 입니다 (정답지에만 있음).

| 모델 | 참값 대비 RMSE | 편향 | 관리기준(100) 초과 328시간 중 적중 | 오경보 |
|---|---:|---:|---:|---:|
| **물리모델** | **2.04** mg/Sm³ | +0.90 | **311** | 132시간 |
| ML 다항릿지(2차) | 11.83 | +10.23 | 327 | 855시간 |
| ML 그래디언트 부스팅 | 19.66 | −18.70 | **0** | 0 |

* 물리모델 오차 2.04 는 **분석계 자체의 오차(측정 vs 참값 2.83)보다 작습니다.**
* 두 ML 은 반대 방향으로 틀립니다. 다항식은 학습 범위 밖에서 치솟아 늘 과대예측하고
  (그래서 초과는 거의 다 "맞히지만" 오경보가 855시간), 트리 모델은 학습 최댓값에서
  평평해져 **초과 328시간을 하나도 못 잡습니다.** 현업에서 흔히 쓰는 쪽이 후자입니다.

### 잔차 변화점 — 모델이 설명 못 한 변화 (`calib/diagnostics.py`)

원시 신호의 계단은 증설·설정 변경과 센서 교체를 구분하지 못합니다. 물리모델은 입력이
만든 변화를 설명하므로, **잔차에 남은 계단은 모델 밖의 변화**입니다.

| 숨긴 사건 | 잡힘 | 툴의 해석 |
|---|---|---|
| 4/7 레시피 변경 (비계측) | NOx +3.42 | 단독 변화 — 계측기이거나 이 관측에만 닿는 공정 변화 |
| 5/28 정압 전송기 교체 +12 | 정압 +13.2 | 단독 변화 |
| 6/21 충전재 세정 | 차압 −26.7, 유량 +487, 정압 −8.0, NOx −3.0 **동시** | 공정 변화 |
| 7/15 분석계 교체 −3 | NOx −3.47 | 단독 변화 |

그 밖에 잡힌 것:
* 7/1 NOx −2.11 — "같은 날 순환수(SCR.L)가 바뀌었습니다. 모델이 그 효과를 실제와 다르게
  예측합니다 — 구성방정식을 점검하세요." **맞습니다.** 모델의 NTU 지수(0.55)가 실제
  (0.62)와 다르게 넣어 둔 것이 순환수를 바꾸자 드러났습니다.
* 2/2 NOx −3.06 — 2/1 분석계 수동 교정으로 1월 드리프트가 0 으로 돌아간 것.
* 8/17 NOx +1.96 — 정답지에 대응하는 사건 없음. 8월 드리프트(하루 +0.12)가 쌓이는
  램프를 계단으로 쪼갠 것으로 보입니다. 월간 드리프트 리셋 7번 중 계단으로 잡힌 것은
  2월 1번뿐입니다 — 램프는 계단 탐지로 잘 안 잡힙니다.

계단 크기가 계측 불확도의 절반 미만이면 버립니다. 처음엔 하루 중앙값이 워낙 조용해서
차압 1 mmAq 계단도 z=216 으로 잡혀 25건이 나왔습니다 (오염이 서서히 진행되는 램프를
여러 계단으로 쪼갠 것). 통계적 유의성이 아니라 **실무적 크기**로 거릅니다.

## 4. 정직하게 말해야 할 것

**정제를 안 하면?** 같은 설정에서 값 정제만 끄고 다시 돌렸습니다.

| | 물리 (참값 대비) | ML 다항 (참값 대비) | 물리 (측정값 대비) |
|---|---:|---:|---:|
| 정제 적용 | 2.04 | 11.83 | 3.46 |
| 정제 없음 | 2.05 | 19.39 | 9.72 |

물리모델이 거의 안 변한 것은 **운**입니다. 보정은 150행 표본으로 하는데, 이번 표본에는
교정 창 값이 한 점도 걸리지 않았습니다(확인함). 정제 효과가 드러난 곳은 ML(11.8→19.4)과
**측정값 대비 평가**(3.46→9.72)입니다 — 정제하지 않으면 좋은 모델을 좋은 모델로 알아볼
수조차 없습니다.

**보정된 파라미터 값은 '진짜 값'이 아닙니다.** 예측은 맞지만 개별 값은 다릅니다.

| 파라미터 | 보정값 | 진짜 | 비고 |
|---|---:|---:|---|
| DRY 가동 배출 | 9.03 mg/s | 8.2 → 9.4 (4/7) | 두 체제의 평균에 가깝다 |
| CVD 가동 배출 | 7.53 mg/s | 4.3 | 다른 오차를 흡수 |
| NTU 계수 | 8.77 | 11.5 | 〃 |
| 메인 덕트 저항 | 15.6 | 22 → 25 | 보정하지 않은 팬 마모를 흡수 |
| 충전층 저항 | 66.5 | 62 → 75 (6/21 후 55) | 오염 진행의 평균 |

식별성 진단은 `ef_idle` 하나만 경고했습니다. **모델 구조 오차를 파라미터가 흡수하는
것은 식별성 진단으로 잡히지 않습니다.** 그래서 이 값들을 설비 진단(덕트가 몇 % 막혔나)에
그대로 쓰면 안 됩니다. 잔차 변화점(7/1 순환수 변경일의 계단)처럼 구조 오차의 흔적을
보여주는 것은 있지만, 파라미터를 물리적 해석에 쓰려면 모델을 먼저 검증해야 합니다.

**그 밖의 한계**
* 물리모델도 편향 +0.9 가 있습니다. 6/21 세정으로 효율이 복원된 것을 모르고, 4/7 이전
  배출계수가 섞여 있기 때문입니다. 잔차 변화점이 그 날짜들을 짚으므로, **변화점 이후
  데이터로 다시 보정**하는 것이 다음 단계입니다 (지금은 사람이 판단).
* 이 데이터의 참값은 툴과 같은 모델 구조에서 나왔습니다. 모델 오차(NTU 지수, 팬 마모)와
  비계측 변화를 넣었지만, 현장은 이것보다 더 다를 수 있습니다. **실데이터로 다시 채점해야
  합니다.**
* 가동율(MES)이 1시간 갱신이라 시간 안의 변동은 어떤 모델도 설명할 수 없습니다.
  툴이 그렇다고 알려줄 뿐 해결하지는 않습니다.
