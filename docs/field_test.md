# 현장형 더미 데이터 스트레스 테스트

실데이터가 없는 상태에서 "현장 데이터를 넣으면 정말 돌아가는가"를 확인하려고,
**일부러 지저분하게 만든 8개월치 데이터**를 만들어 툴 전체를 통과시켰습니다.
문제를 어디에 숨겼는지 정답지를 따로 두고, 툴이 그것을 얼마나 찾아내는지 채점했습니다.

```bash
python examples/nox_field/make_field_data.py              # 개발용 데이터 + 정답지 (약 7분)
python examples/nox_field/make_field_data.py --holdout --seed 7777 \
       --out examples/nox_field/data/holdout             # 처음 보는 시험용 데이터
python examples/nox_field/evaluate.py                     # 채점 → out/scorecard.md
python examples/nox_field/evaluate.py --quick --data examples/nox_field/data/holdout \
       --name scorecard_holdout                           # 시험용 데이터 채점
```

이 문서의 수치는 전부 위 명령을 실제로 돌려서 나온 값입니다 (`out/scorecard*.json`).

## 0. 검증 원칙 — 미래이면서 외삽, 누수 없이

물리모델과 ML 의 차이는 **학습 데이터에 없던 조건**에서만 드러납니다. 학습 범위 안에서는
ML 도 잘 맞히므로, 그런 검증으로는 물리모델이 필요한지 알 수 없습니다. 그래서 모든
비교 검증은 두 조건을 동시에 만족해야 합니다.

1. **미래** — 검증 시점이 전부 학습 마지막 시점보다 뒤이고, 그 사이에 간격(엠바고)이 있다.
2. **외삽** — 검증 시점의 운전 입력이 학습 운전영역(포락선) 밖이다.

툴은 이 둘을 매번 검사해서 보고서 맨 위에 적습니다 (`data/split.py`). 어기면 경고합니다.
이 데이터의 보정 검증은:

* 학습 ~5/31, 검증 6/10~8/31. **검증 행 중 학습보다 과거 0개, 간격 9.0일**
* **검증 행의 100% 가 학습 운전영역 밖** (6/10 증설로 DRY 장비 24→30대, 여름 외기, 가동율 상승)
* 채점은 외삽 행에서만 합니다 (이 경우 전부).

## 1. 무엇을 숨겼나

물리는 `nox_stack` 모델로 7만 회 정상상태를 풀어 만들었습니다. 다만 **현장은 모델과
다르게** 만들었습니다 — 모델이 모르는 변화와 모델 자체의 오차를 넣었습니다.

| 층 | 숨긴 것 (개발용 데이터) |

| **운전** | 1/28 설 연휴 감산 · 5/3~5 팹 정기 PM · 4/15, 6/21 순환펌프 정지(유량 0) · **6/10 DRY 장비 24→30대 증설** · 7/1 순환수 증량 · 여름 폭염 |
| **계측** | NOx 분석계 매일 03:00 영점→스팬(160) 자동 점검 · 월 1회 수동 교정 사이 드리프트 · 응답 지연 · 7/15 분석계 교체(−3) · 유량계 56시간 고착 · 열전대 단선(999.9, −40) · 5/28 정압 전송기 교체(+12 mmAq) · IMP 지류 유량계 4/1 고장 · 헤더 유량계 +3% 게인 · 예비 온도계 +0.45 ℃ · MES 가동율 1시간 갱신 |
| **파일** | CP949 · 태그/설명/단위 3행 헤더 · 첫 컬럼 '일시' · 1~3월 `2025-01-01 오후 3:05` 표기와 천 단위 콤마 · `Bad`/`Comm Fail`/`I/O Timeout`/`Maint`/`#N/A` · 월별 파일을 이어 붙이며 생긴 중간 헤더, 72행 중복, 7·8월 순서 뒤바뀜 · 3/9 하루 누락 · 끝 콤마 빈 컬럼 · 빈 줄 · 방해 컬럼(pH, 레벨, 펌프 교대, 죽은 예비 입력) |

시험용 데이터(`--holdout`)는 같은 종류의 문제를 **다른 크기·다른 날짜·다른 방향**으로
숨깁니다 (5절).

## 2. 누수 감사 — 검증 데이터가 학습 쪽으로 새던 곳

툴의 모든 경로를 "검증 구간의 정보가 학습 쪽 처리에 들어가는가"로 다시 읽었습니다.
여덟 곳이 새거나 검증을 쉽게 만들고 있었습니다.

| # | 어디 | 새던 것 | 고친 뒤 |
|---|---|---|---|
| 1 | 예제 보정·후보 비교 분할 | 가동율 **값**으로 갈랐다(학습 ≤0.55, 검증 ≥0.62). 값으로는 외삽이지만 검증 행의 **88%** 가 학습보다 과거 — 같은 날의 계측 편향을 양쪽이 공유 | 시간순 + 하루 간격. 예제 데이터를 램프업이 있는 형태로 다시 만들어 검증이 **미래이면서 100% 외삽** |
| 2 | 값 이상 탐지(정제) | 전체 기간을 한 번에 봤다. 잡음 척도, 교정 창 '매일 반복' 판정에 검증 구간 값이 들어감 | 학습·간격·검증을 **따로** 판정 (`assess_parts`) |
| 3 | 대리모델 교차검증 | 블록 k-fold — 검증 블록 **뒤의** 블록까지 학습에 씀 (미래로 과거를 맞힘) | 전진 교차검증: 앞 블록만으로 학습, 지연 길이만큼 간격 |
| 4 | 지연 탐색 | ±12행을 봤다. 음수 지연은 **피처의 미래 값**으로 현재를 설명 | 0 이상만 |
| 5 | 분석의 '예측' 성능 | 굴뚝 유량·차압처럼 **같은 시각에 측정되는 결과값**을 입력으로 쓴 점수를 예측 성능처럼 보고 | '현재값 추정'으로 이름을 바꾸고, **미래 예측은 미리 알 수 있는 운전 입력만으로** 따로 잰다 |
| 6 | 분석 분할 | 시간순이었지만 경계에 간격이 없음 | 하루 엠바고 (`split.embargo`) |
| 7 | 구성방정식 후보 선택 | 검증 구간으로 **고르고** 같은 구간 오차를 성능으로 보고 | 학습/선택/시험 세 구간. 시험 구간은 고르는 데 쓰지 않는다 |
| 8 | 이 채점 자체 | 탐지 임계값을 이 데이터를 보며 조정했다 | 다른 시드로 만든 **처음 보는 데이터**로 다시 채점 (5절) |

그리고 공정한 비교를 위해 ML 기준모델에 **그래디언트 부스팅**을 추가했습니다. 현업에서
실제로 많이 쓰는 쪽이 다항식이 아니라 트리 모델이기 때문입니다.

**실측한 영향.**

| | 고치기 전 | 고친 뒤 |
|---|---:|---:|
| 이 데이터의 대리모델 설명력 R² (#2~#4, #6 을 모두 고친 결과) | 0.719 | **0.663** |
| 예제(`nox_stack`) — 같은 데이터·같은 피처, 교차검증 방식만 바꿈 | 0.664 (블록 k-fold) | **0.522** (전진) |

미래로 과거를 맞히면 설명력이 부풀려집니다. 고치기 전 숫자는 틀린 것이 아니라
**질문이 달랐던** 것입니다 — "이미 본 시기 사이를 메우는가"와 "아직 오지 않은 시기를
맞히는가"는 다른 질문이고, 운영에 필요한 것은 뒤쪽입니다.

**테스트로 박아 둔 것** (`tests/test_leakage.py`, `tests/test_analyze.py`):
* 검증 구간을 완전히 망가뜨려도(잡음 10배, 값 999.9 고정) **학습 구간 정제 결과가 한 비트도
  바뀌지 않는다**
* 값 기준 분할은 "미래 예측 검증이 아닙니다", 학습 범위를 오가는 시간순 분할은
  "외삽 검증이 아닙니다"로 걸린다
* 교차검증의 모든 fold 에서 학습 최대 행 < 검증 최소 행, 간격 유지
* 타깃이 피처보다 앞서는 데이터에서도 지연은 0 이상
* 분석의 미래 예측은 선언한 운전 입력만 쓴다 (결과 변수 유량은 제외)

## 4. 고친 뒤 — 채점 결과 (개발용 데이터)

### 파일 읽기 (`data/ingest.py`)

주입한 파일 결함을 전부 찾아 고치고, 고친 내역을 문장으로 보고합니다.

* CP949, 3행 헤더 인식 — 단위 행에서 23개 컬럼의 단위를 읽음 (`mg/Sm³`→`mg/Sm3`, `㎥/h`→`m3/h`, `℃`→`degC`, `대`→`1`)
* 시각: `오전/오후` 25,671행 + ISO 44,018행, 해석 불가 **0**
* 반복 헤더 6행, 중복 **72행 (주입 72)**, 순서 뒤바뀜 2곳, 빈 컬럼 1개
* 상태 문자열: Bad 44,090 · Comm Fail 1,728 · I/O Timeout 810 · Maint 720 · #N/A 576
* 천 단위 콤마 25,547셀
* 5분 격자 69,984행으로 정렬, 빠진 시각 367개(3/9 하루 포함)는 빈 행으로

### 값 이상 탐지 (`data/quality.py`)

| 태그 | 주입 | 탐지 | 놓침 | 오탐 |
|---|---:|---:|---:|---:|
| 굴뚝 NOx (교정 창 1,074 + 스파이크 12) | 1,086 | 1,086 | 0 | 0 |
| 굴뚝 유량 (고착 671 + 스파이크 14) | 685 | 685 | 0 | 0 |
| 굴뚝 온도 (단선) | 6 | 6 | 0 | 0 |

정상 점 1,617,856개 중 **오탐 0**. 정기 교정은 "매일 03:00~03:25 반복 — 분석계
영점/스팬 점검으로 보입니다"로 따로 분류합니다. 펌프 정지(유량이 정확히 0)는
**고착이 아니라 설비 정지로 보고 지우지 않습니다** — 그 구간 NOx 상승은 진짜 공정이고,
모델이 배워야 하는 것입니다. 탐지는 학습·간격·검증 구간을 따로 합니다 (2절 #2).

만들면서 실제로 걸린 함정 두 개:
* 교정 창 옆 행이 비어 있으면 이동 중앙값이 교정값에 끌려가 멀쩡한 이웃 점 5개가
  스파이크로 잡혔습니다 → 교정 창을 먼저 빼고 다시 봅니다.
* 기존 예제의 인버터 주파수(0.01 단위 반올림)에서 잡음 추정이 0 에 붙어 오탐 4건이
  났습니다 → 잡음 하한을 신호 분해능으로.

**단, 이 표는 임계값을 이 데이터를 보며 맞춘 결과입니다.** 처음 보는 데이터의 결과는 5절.

### 데이터 주도 분석 (L0~L3)

* **현재값 추정** (같은 시각에 측정되는 유량·차압 등도 입력): 전진 교차검증 R² **0.663**
* **미래 예측** (미리 알 수 있는 운전 입력만, 시간순 분할 + 하루 간격): 검증 RMSE 9.18 mg/Sm³.
  학습 운전영역 밖 23,872행에서 **9.64**, 안쪽 2,805행에서 **3.04** — 같은 모델이 범위
  안에서는 3배 잘 맞힙니다. 차이는 외삽에서만 납니다.
* **"F2_FAB_DRY_EQP_CNT 는 학습 구간에서 변하지 않아 대리모델이 이 변수의 효과를 배울 수
  없습니다"** — 증설처럼 ML 이 원리적으로 못 보는 변화를 스스로 짚습니다.
* 보존식이 **계측기를 진단**합니다:
  * 지류 4개 합 = 헤더 → "헤더 유량계가 지류 합보다 **+3.0%** 높게 읽습니다 — 계측기
    교정 오차로 보입니다" (주입 3%). IMP 지류 유량계가 4월에 죽었는데도, 살아 있던
    1~3월 구간으로 찾았습니다.
  * 굴뚝 온도 2개 → "예비 온도계가 평균 **0.451 ℃** 높게 읽습니다 — 이중화 계측의
    영점 오차" (주입 0.45). ℃ 처럼 영점이 임의인 단위는 비율 대신 차이로 말합니다.

(분석의 미래 예측은 전체 기간의 앞 60% 로 학습해 나머지를 맞히는 별도 분할이라 아래
보정 검증과 구간이 다릅니다. 두 숫자를 직접 비교하지 마세요.)

### 물리모델 vs ML — 1~5월로 학습, 증설 후 6/10~8월 예측

검증은 **미래이면서 100% 외삽**입니다 (0절). 같은 학습 데이터, 같은 운전 입력
(가동율·대수·외기·팬·순환수)으로 비교했습니다. **참값**은 계측 오차가 없는 진짜 NOx
입니다 (정답지에만 있음).

| 모델 | 참값 대비 RMSE | 편향 | 측정값 대비 RMSE | 관리기준(100) 초과 328시간 중 적중 | 오경보 |
|---|---:|---:|---:|---:|---:|
| **물리모델** | **2.04** mg/Sm³ | +0.90 | 3.46 | **311** | 132시간 |
| ML 2차 다항 | 11.83 | +10.23 | 12.36 | 327 | 855시간 |
| ML 그래디언트 부스팅 | 19.66 | −18.70 | 19.39 | **0** | 0 |

* 물리모델 오차 2.04 는 **분석계 자체의 오차(측정 vs 참값 2.83)보다 작습니다.**
* 두 ML 은 반대 방향으로 틀립니다. 다항식은 학습 범위 밖에서 치솟아 늘 과대예측하고
  (그래서 초과는 거의 다 "맞히지만" 오경보가 855시간), 트리 모델은 학습 최댓값에서
  평평해져 **초과 328시간을 하나도 못 잡습니다.**

### 잔차 변화점 — 모델이 설명 못 한 변화 (`calib/diagnostics.py`)

원시 신호의 계단은 증설·설정 변경과 센서 교체를 구분하지 못합니다. 물리모델은 입력이
만든 변화를 설명하므로, **잔차에 남은 계단은 모델 밖의 변화**입니다.

| 숨긴 사건 | 잡힘 | 툴의 해석 |
|---|---|---|

쓰려면 모델을 먼저 검증해야 합니다.

**그 밖의 한계**

  배출계수가 섞여 있기 때문입니다. 잔차 변화점이 그 날짜들을 짚으므로, **변화점 이후
  데이터로 다시 보정**하는 것이 다음 단계입니다 (지금은 사람이 판단).
* 이 데이터의 참값은 툴과 같은 모델 구조에서 나왔습니다. 모델 오차(NTU 지수, 팬 마모)와
  비계측 변화를 넣었지만, 현장은 이것보다 더 다를 수 있습니다. **실데이터로 다시 채점해야
  합니다.**

  물리모델도 못 맞히고, 잔차 변화점으로 알려줄 뿐입니다.
