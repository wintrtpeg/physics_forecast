# 구성방정식 후보 추천 — 코드가 추리고, 사람이 고른다

물리모델은 두 종류의 식으로 되어 있습니다.

| 종류 | 예 | 후보가 되나 |
|---|---|---|
| 보존법칙·상태식 | 질량·에너지·화학종 보존, 이상기체, 건조 기준 환산 | **아니오.** 데이터와 무관하게 성립하고, 외삽의 근거입니다 |
| 구성방정식(closure) | 스크러버 제거효율, 압력손실, NOx 배출계수 | **예.** 원래 경험식이라 형태가 여럿입니다 |

앱 4단계(모델·실행)의 **구성방정식 — 후보에서 고르기** 카드에서 "데이터로 후보 비교하기"를
누르면, 코드가 데이터와 계통 특성으로 후보를 추리고 근거를 붙입니다. LLM 은 쓰지
않습니다. 추천대로 골라 두지만 **최종 선택은 사용자**가 라디오 버튼으로 합니다. 고른 식은
실행·결과의 모델 설명·설정 YAML(`model.closures`)에 그대로 들어갑니다.

```bash
pf closures examples/nox_field/calibration.yaml            # CLI 도 같은 엔진
pf closures examples/nox_field/calibration.yaml --slot SCR.eta
```

## 후보 목록 (`src/pforecast/lib/closures.py`)

계통에 있는 컴포넌트 종류가 슬롯을 정합니다. 슬롯마다 **하한선**(가장 단순한 형태)과
**이론 표준형**(기본값)을 표시합니다.

| 슬롯 | 후보 | 역할 |
|---|---|---|
| 스크러버 NOx 제거효율 | η = 상수 | 하한선 |
| | η = η_max·(1 − e^−NTU), NTU = a·(L/G)^b | 이론 표준형 (기본) |
| | 같은 식에서 L/G 지수 b 까지 보정 | 확장 |
| | η = η_max·(L/G)/(k + L/G) | 대안 (포화형) |
| | NTU 에 가스 온도항 (T/313 K)^c 추가 | 확장 |
| 장비군 NOx 발생량 | 대수·가동률·배출계수 (대기 0) | 하한선 |
| | 대수·(대기 배출계수 + 가동률·가동 배출계수) | 이론 표준형 (기본) |
| | 가동 항을 가동률^γ 로 | 확장 |
| 충전층·덕트 압력손실 | Δp = K·ṁ\|ṁ\|/ρ | 이론 표준형·가장 단순 (기본) |
| | 유량 지수 n 을 보정 (천이 영역) | 확장 |

기본 후보를 명시해도 모델은 **한 비트도 바뀌지 않습니다** (`tests/test_closures.py`).

## 추천 순서 — 싼 것부터

**학습 기간만 씁니다.** 학습 기간을 다시 시간순으로 나눠 앞부분으로 보정하고, 1일을 띄운
뒤 끝부분(검증, 학습 기간의 25%)으로 채점합니다. 사용자가 정한 예측 기간은 받지도 않습니다
(예측 기간 값을 망가뜨려도 엔진이 받는 데이터가 같다는 것을 테스트로 확인).

1. **영향** — 슬롯의 현재 식 파라미터를 10% 바꿔 예측값이 1% 미만으로 변하면 "영향 작음"으로
   두고 비교하지 않습니다.
2. **변화 폭** — 후보를 가르는 변수(L/G, 가스 온도, 가동률, 유량)의 학습 데이터 변화 폭
   (5~95% 분위 폭 / 중앙값)이 5% 미만이면 그 후보는 "구별 불가"입니다. 데이터가 흔들지 않은
   방향은 어떤 검증으로도 가릴 수 없습니다.
3. **관측 민감도** — 후보에 새로 생기는 파라미터를 10% 바꿔도 관측이 계측 불확도의 0.1배도
   안 움직이면 "구별 불가"입니다. 불확도를 적지 않은 관측은 학습 값 크기의 2% 로 봅니다.
4. **잔차 진단** — 현재 식의 잔차와 가르는 변수의 상관을 근거로 보여줍니다.
5. **보정 + 검증** — 남은 후보만 같은 행(1시간 평균 60행, 드문 운전상태 포함)으로 보정해
   검증 구간의 **학습 운전영역 밖 행**에서 RMSE 를 냅니다.

공정하게 비교하려고 **현재 식은 사용자가 정한 보정 그대로** 채점합니다. 다른 후보는 현재
식과 같이 쓰는 파라미터는 사용자 선택을 따르고, **새로 생기는 파라미터만** 더 풉니다.

## 추천 규칙

* 기본은 **현재 식 유지**입니다. 다른 후보는 검증 오차가 **2% 이상** 낮고, 1차 자기상관으로
  깎은 유효 표본수로 **2 표준오차 이상** 차이 날 때만 추천합니다.
* 후보에만 있는 파라미터가 식별되지 않거나(상대표준오차 > 50%, |상관| > 0.95) 보정 경계에
  붙으면 **제외**합니다. 제외한 후보의 검증 오차가 더 낮았으면 그 사실도 적습니다.
* 하한선보다 현재 식이 낫다는 근거가 없으면 그렇다고 적습니다.
* 검증 구간 앞·뒤 절반 **모두에서** 현재 식보다 나아야 바꾸자고 합니다. 한쪽에서만 나으면 "불안정".
* 상태 표시: 추천 · 근소하게 나음(유의하지만 2% 미만) · 불안정 · 비슷함 · 나쁨 · 제외 · 구별 불가 · 비교 안 함.

## 실제로 돌려 본 결과

`examples/nox_field/data/field_raw.csv` (현장형 더미, 5분 × 8개월). 앱과 같은 설정으로 학습
2025-01-01 ~ 05-26 만 넣었습니다. 보정 01-01 ~ 04-19, 검증 04-20 ~ 05-26 (831시간, 외삽 행 76%).
보정 8회, 327초.

| 슬롯 | 예측값 영향 | 결과 (검증 RMSE, mg/Nm3) |
|---|---|---|
| SRC_DRY 발생량 | 4.48% | **현재 식 유지.** 가동률 비례(하한선) 5.29 vs 현재 5.17 — 구분 안 됨. 비선형 부하형 4.21 은 γ 의 상관 +0.99 로 식별되지 않아 제외. 현재 식의 배출계수도 상대표준오차 67% 로 식별이 약하다고 경고 |
| SRC_CVD 발생량 | 2.18% | **현재 식 유지.** 하한선 5.16 vs 현재 5.17 — 구분 안 됨. 비선형 부하형 3.89 는 γ 의 상관 +0.95 로 제외 |
| 스크러버 제거효율 | 1.98% | **현재 식(NTU 거듭제곱형) 유지, 포화형은 "근소하게 나음".** 포화형 5.07 vs 5.17 — 유의하고 검증 앞·뒤 절반 모두 낫지만 개선 1.99% 로 2% 문턱 아래. NTU 지수까지 보정하는 형태(5.12)는 지수가 식별되지 않아 제외 (상관 +1.00, L/G 변화 폭 12.6%). 상수(하한선)는 보정 경계에 붙어 제외. 가스 온도항은 온도 변화 폭 3.1% 라 구별 불가 |
| 충전층 압력손실, 소형 장비군 2개, 덕트 5개 | 0.02 ~ 0.77% | 영향 작음 — 비교 안 함 |

같은 데이터를 CLI 설정(`examples/nox_field/calibration.yaml`, 학습이 5/31 까지로 5일 더 김)으로
돌리면 검증 04-24 ~ 05-31 에서 포화형 5.173 vs 현재 5.288 (−2.2%, 유의, 앞·뒤 절반 모두 나음)
이라 **포화형을 추천**합니다.

**해석.** 이 더미 데이터는 NTU 거듭제곱형으로 만들었지만 L/G 지수가 0.62 이고, 모델은 지수를
설계값 0.55 로 고정해 보정하지 않습니다. 지수를 보정하는 후보는 데이터가 L/G 를 충분히
흔들지 않아 식별되지 않았습니다. 그래서 자유 파라미터를 가진 포화형이 지수 오차를 흡수해
두 기간 모두 **같은 방향으로** 조금 낫게 나왔고, 크기가 2% 문턱에 걸쳐 기간에 따라 추천이
갈렸습니다. 예측 기간(05-28 ~ 08-31, 선택에는 쓰지 않음)에서 사용자가 포화형을 골라 실행하면
외삽 행 RMSE 가 3.01, 현재 식은 3.25 였습니다.

그래서 화면은 문턱 근처의 후보를 숨기지 않고 "근소하게 나음"으로 보여주며, 바꿀지는 사용자가
정합니다. 비선형 부하형(−18%, −25%)처럼 검증 오차가 크게 낮아도 파라미터가 식별되지 않으면
제외하고, 그 사실을 같이 적습니다.

## 새 후보 추가하기

`lib/closures.py` 에 `Closure` 를 하나 더하면 끝입니다. 컴포넌트·앱·추천 엔진은 고칠 필요가
없습니다.

```python
Closure(
    "my_form", "새 형태 이름",
    Law(CLOSURE, "NOx 제거효율 — 새 형태", "η = `eta_max` · tanh(`k` · L/G)"),
    {"eta_max": _P_ETA_MAX, "k": ParamSpec(300.0, "1", "기울기", lo=1e-3, hi=1e5, tunable=True)},
    lambda s, c: s.eta_max * S.tanh(s.k * c["LG"]),            # 모델이 푸는 식
    lambda pv, c: pv("eta_max") * math.tanh(pv("k") * c["LG"]),  # 초기값용 같은 식
    fit=("k",), needs=("LG",), note="한 줄 설명"),
```

* 보정 파라미터의 **설계값은 0 이 아니어야** 합니다 (보정기가 설계값의 0.2~5배로 경계를 잡음).
* 수치 식과 심볼릭 식이 같은 값을 내는지, 식의 파라미터가 실제로 있는지, 보정 파라미터가
  구성방정식에만 있는지는 테스트가 모든 후보에 대해 검사합니다.
