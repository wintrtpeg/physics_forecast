# 물리모델 개선 이력 — 피드백 → 가설 → 변경 → 측정 → 채택/기각

물리모델이 학습 범위 밖을 더 잘 맞히도록 반복해서 고친 기록입니다. 각 반복은 툴이 준
**피드백**(식별성 경고, 잔차 변화점, 파라미터 시변성 …)에서 가설을 세우고, 바꾸고, 쟀습니다.
**실패한 시도도 전부 남깁니다.** 무엇이 안 되는지와 왜 안 되는지가 다음 반복의 출발점이기
때문입니다.

이 문서의 수치는 전부 실제로 돌려서 얻은 값입니다.

---

## 평가 체계 — 판단에 쓴 데이터와 안 쓴 데이터

설계를 고르는 과정 자체가 누수가 되지 않도록 데이터를 셋으로 나눴습니다.

| 용도 | 데이터 | 언제 봤나 |
|---|---|---|
| **내부 폴드** — 설계 비교 | 학습 구간(1~5월) 안에서 1~3월 → 4월, 1~4월 → 5월 | 매 반복 |
| **개발용 시험** — 긴 외삽 확인 | 1~5월 보정 → 증설 후 6/10~8/31, 참값 대비 NOx RMSE. 데이터 5벌: 개발용(시드 20250101), 7777, 101, 202, 303 | 매 반복 (그래서 여기에 맞춘 셈이다) |
| **최종 확인** | 시드 5150, 8080 — 개선을 시작할 때 만들어 두고 **설계를 확정할 때까지 열지 않음**. 여기서 예측 루프 버그를 찾았으므로(12번) 수정 후 시드 6060, 9191 을 새로 만들어 한 번 더 | 마지막 한 번씩 |

시드 101·202·303 은 두 벌만으로는 개선과 우연을 구분할 수 없어서 중간에 추가했습니다
(6번 참고). 개발용 시험의 RMSE 는 5분 행 12개 중 1개로 잰 값이라 `evaluate.py` 의 전체
행 값과 조금 다릅니다. 문서의 최종 수치는 `evaluate.py` 로 다시 쟀습니다.

### 2~5. 왜 '최근 상태로 다시 맞추기'가 실패했나

내부 폴드(1~2개월 앞)에서는 가장 좋았는데, 증설 이후 석 달을 맞히는 실제 외삽에서는
세 배로 나빠졌습니다. 정답지로 원인을 나눠 봤습니다.

1. **좁은 창엔 운전 다양성이 없다.** NOx 상승을 어느 파라미터에 붙일지 데이터가 정하지 못한다.
   '대당 대기 배출'에 붙이면 장비 대수에 비례해 커지므로 24 → 30대 증설에서 과대예측이 된다.
   장비 대수는 학습 내내 24 였으므로 **어떤 내부 폴드도 이 방향을 검증하지 못한다.**
2. **계측 드리프트를 공정으로 흡수한다.** 분석계는 하루 +0.12 씩 올라가다 매월 1일 교정으로
   돌아온다. 학습 끝(5월 말)은 드리프트가 최대(+3.5)인 시점이다.
3. **유량 계통 상태도 끌려간다.** 오염이 진행된 5월 말의 저항으로 맞추면 유량이 줄고 희석이
   줄어 농도가 오른다. 그런데 미래에는 충전재 세정(정비)으로 저항이 다시 떨어진다.
4. **지금의 작은 편향은 일부 운이다.** 드리프트(+1.8 평균)와 레시피 변경을 평균한 과소예측이
   서로 상쇄하고 있었다 (5번). 한쪽만 고치면 오히려 나빠진다.

그래서 파라미터가 시간에 따라 움직인다는 사실은 **예측에 쓰지 않고 진단으로 보고**합니다
(`pf improve` 의 파라미터 시변성·상태 변동 폭).

### 8. 권고를 따랐는데 효과가 없었던 이유 — 그리고 잘못된 해석 하나

현장형 데이터는 NTU 지수를 모델(0.55)과 다르게(0.62) 만들어 두었습니다. 증설 후 운전점
(DRY 30대, 가동율 0.8~0.9, 61 Hz)에서 순환수를 33 → 42 m³/h 로 늘리면 NOx 가 참값 구조로는
−1.64%, 다른 값은 그대로 두고 지수만 0.55 로 바꾸면 −2.02% 줄어듭니다 (모델로 직접 계산).
차이 0.4%p, 100 mg/Sm³ 기준 약 0.4 — **지수 오차가 NOx 에 주는 영향이 원래 작아서** 단계
시험으로 식별할 정보 자체가 없었습니다.
'검증된 적 없는 방향'은 경고이지 오차 확정이 아닙니다.

이 계산 중에 기존 문서의 틀린 해석을 찾았습니다. `docs/field_test.md` 는 7/1 NOx 잔차 계단
(−2.11)을 "NTU 지수 오차가 순환수 증량에서 드러난 것"이라고 적었습니다. 정답지로 보면 이
계단은 **같은 날 월간 교정으로 분석계 드리프트가 0 으로 돌아간 것**입니다 (계측 오차 주간
중앙값 3.09 → 0.35). 채점기가 날짜가 맞는 정답을 첫 번째 하나만 붙였기 때문에 생긴 오해라,
채점기가 겹치는 정답을 **전부** 적도록 고쳤습니다.

### 12. 최종 확인이 찾아낸 버그 — 좋아 보이는 숫자를 의심하라

설계를 확정하고 최종 확인용 시드(5150, 8080)를 처음 열었을 때, 5150 의 물리모델 RMSE 는
4.19 로 그럴듯했지만 관리기준 초과 시간의 분모가 71시간이었습니다 (같은 데이터의 ML 은
374시간). 물리모델이 **검증 구간 대부분을 풀지 못했는데** 채점이 푼 행만으로 된 것입니다.

* 원인: 시점별 정상상태를 이전 시점의 해에서 출발해 푼다. 순환펌프가 선 시점(액가스비 ≈ 0)의
  해에서 펌프가 다시 돈 시점(42 m³/h)을 풀면 뉴턴법이 발산한다. 실패하면 출발점이 갱신되지
  않으므로 그 뒤가 전부 같은 나쁜 출발점에서 시작해 실패했다. 세정(펌프 정지)이 순환수 증량
  뒤에 오는 데이터는 101·303·8080 도 있었지만 그쪽은 수렴했다 — 5150 의 보정값과 겹쳐야
  발산한다. 어떤 값에서 발산하는지까지는 확인하지 않았다. 수정은 출발점만 바꾸므로 원인과
  무관하게 동작한다.
* 수정: 실패하면 모델 기본 출발점에서 한 번 더 푼다 (`calib/runner.solve_with_fallback`, 보정과
  예측 모두). 세 시점짜리 재현 사례를 회귀 테스트로 박았다.
* 채점기: 초과 시간의 분모를 참값으로만 정하고, 예측을 못 낸 시간은 '놓침'으로 센다.
  '예측한 행' 비율을 표에 적는다. 워크플로와 리포트도 수렴 실패 행 수를 경고한다.
* 개발용 5벌은 수정 전후 결과가 같았다 (전부 수렴률 100%) — 채택 판단은 그대로 유효하다.
* 5150·8080 은 이 버그를 찾는 데 한 번 봤으므로, 최종 확인용 시드 **6060·9191** 을 새로
  만들어 수정 후 한 번만 채점했다.

### 10~11. 예측 구간은 공분산이 아니라 상태 변동으로

파라미터 공분산을 예측 조건으로 전파하면 1σ 가 ±0.5~0.8 mg/Sm³ 입니다. 실제 편향은 202 에서
+2.7 로, 공분산으로 보면 5σ 가 넘습니다. 오차의 대부분은 파라미터를 부정확하게 잰 데서가
아니라 **설비 상태가 변해서** 옵니다 (레시피, 오염, 정비, 계측 드리프트).

그래서 학습 기간을 네 토막으로 나눠 토막마다 다시 맞춘 파라미터로 미래를 각각 풀었습니다.
그 폭(5.6~9.3 mg/Sm³)이 5벌 모두에서 참값 평균을 덮었습니다. 파라미터 불확도 전파는 대신
**어떤 파라미터가 외삽을 흔드는지** 알려줍니다 — 5벌 모두 DRY 가동 배출계수가 43~55%.

## 교훈 (CLAUDE.md 에 규칙으로 반영)

1. **짧은 내부 폴드는 좁은 창 재보정을 과대평가한다.** 학습에서 한 번도 변하지 않은 방향은
   어떤 내부 폴드로도 검증되지 않는다.
2. **좁은 기간으로 다시 맞춰 예측하지 말 것.** 운전 다양성을 잃으면 귀속이 바뀌고, 계측
   드리프트와 일시적 상태까지 흡수한다.
3. **편향이 작으면 상쇄를 의심하라.** 한쪽만 고치면 나빠질 수 있다.
4. **개선 판단은 데이터 여러 벌로.** 두 벌로는 샘플링 잡음과 개선을 구분하지 못한다.
5. **날짜가 맞는 원인이 여럿이면 전부 적는다.** 첫 번째만 적으면 단정하게 된다.
6. **긴 지평 예측의 구간은 상태 변동으로.** 파라미터 공분산은 무엇을 더 재야 하는지를 말한다.

## 도구가 된 것 — `pf improve`

위 반복을 사람이 매번 하지 않도록 한 바퀴를 명령 하나로 만들었습니다.
**학습 구간만** 쓰고, 예측 구간은 **입력**(미리 아는 값)만 봅니다.

```bash
pf improve examples/nox_field/calibration.yaml     # 약 8분 → out/improve.md
```

1. 보정 설계 후보(행 선택 방식, 잔차가 가리키는 추가 파라미터)를 내부 전진 폴드로 비교.
   복잡한 쪽은 2% 이상 나아야 채택.
2. 잔차 피드백 (점수 검정) — 이미 보정한 파라미터와 구분되지 않는 후보는 따로 표시.
3. 예측 민감도 — 학습 조건 대비 예측 조건에서 불확도가 몇 배로 커지는지, 주범은 누구인지.
4. 파라미터 시변성 — 토막마다 다시 맞춘 값. '계속 증가'(오염), '상쇄'(구분 안 됨), '미결정'.
5. 상태 변동 폭 — 토막별 상태로 예측 구간을 풀어 본 폭.
6. 검증된 적 없는 외삽 방향 — 한 번도 안 변함 / 평소 고정 / 범위 밖(변한 적은 있음).

개발용 데이터에서 실제로 나온 출력의 일부 (`examples/nox_field/out/improve.md`):

